- Porta: lida automaticamente da variável PORT da hospedagem (fallback 80)

IMPORTANTE SOBRE O BUILD
A V10 foi preparada especificamente para reduzir o pico de memória que causou SIGKILL na hospedagem:
- build de produção usa Webpack em vez do Turbopack;
- build worker habilitado;
- otimizações de memória do Webpack habilitadas;
- source maps de produção desabilitados;
- coleta de páginas limitada a 1 worker (experimental.cpus = 1);
- geração estática limitada a 1 página por vez;
- todas as rotas entram em um único lote de geração;
- source maps de prerender desabilitados;
- processo de build recebe limite de heap próprio;
- a porta externa abre ANTES da compilação.

NÃO configure um comando externo que fique repetindo `next build`.
Use apenas:
  npm start

FLUXO DO index.js
1. Abre a porta imediatamente.
2. Se existir .next/BUILD_ID: inicia Next em modo produção.
3. Se não existir: executa build econômica em processo filho.
4. Se a build concluir: inicia produção.
5. Se o processo de build ainda for morto/falhar: inicia fallback de emergência já sob a mesma configuração de 1 worker.

NO LOG CORRETO DA V10.2, procure por:
  Collecting page data using 1 worker
  Generating static pages using 1 worker
Se aparecer 13 workers, a hospedagem ainda está usando o ZIP antigo.

O fallback é uma proteção de disponibilidade; produção compilada continua sendo o modo ideal.
